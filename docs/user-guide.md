# 镜序使用指南

> 写给真正剪片的人：剪辑助理、后期、跟场记对接的人。
>
> 这份文档只讲**当前桌面版已经能做的事**，不讲内部实现。产品定义与工作区划分以 [`app-information-architecture.md`](./app-information-architecture.md) 为准，文档总索引见 [`README.md`](./README.md)。如果本文和界面文案有出入，以界面为准，并把差异记下来反馈。

---

## 0. 先认识四块地方

镜序只做一条链：

```text
原始素材 + 剧本 + 可选场记
→ 认出真实的 Take 和多机位关系
→ 记下 / 修正拍摄事实
→ 把 Take 对到剧本正确位置
→ 看片并做出人工决定
→ 形成可剪的时间线
→ 交给 Final Cut Pro / Premiere Pro
```

打开一个项目后，顶部只有四个一级工作区，分别回答一个问题：

| 工作区 | 回答的问题 | 你在这里主要做什么 |
| --- | --- | --- |
| **素材** | 我拿到了什么？实际拍了什么？ | 看场记、看素材库、看 Take 与机位、看人物 |
| **剧本** | 这些 Take 对应故事哪里？哪里缺、哪里冲突？ | 把 Take 归到正确的剧本段或集数 |
| **审阅** | 哪些需要我看片并作决定？ | 播片、切机位、给 Take 最终决定 |
| **时间线** | 现在能剪成什么样？ | 排列镜头、做交付前检查、导出 |

左侧栏是长期上下文和全局工具：项目列表、**状态中心**、**设置**；新建项目在首页右上角（「新建项目」）。团队审阅、本机素材/换素材盘、删除项目等项目级动作在**项目右键菜单**里（也可选中项目按 `Shift+F10` 打开）。

- **状态中心**：所有后台长任务（扫描素材、转写、匹配、人物识别、索引等）都在这里看进度、看失败、重试或取消。画布上只出现轻量提示，不重复一整套任务面板。
- **设置**：外观、本地 AI 与身份识别、小镜的 AI 能力（模型覆盖）、团队审阅（Team Web）偏好，以及排查用的本机信息。

启动 App 会尝试恢复上次成功打开的工作区；没有可恢复记录时，用「打开工作区」选目录，或用「打开工作区文件」选工作区文件。恢复失败时会停在一个安静的重新定位页，只需要重新定位工作区，项目数据不会被改写。

## 1. 五步主链：从一堆素材到能剪的时间线

### 第一步：找到一个真实的 Take（素材 → Take）

1. 进入项目，点顶部「素材」，在左侧视图里选「**Take**」。
2. 一张 Take 卡片就是一次真实拍摄。卡片标题形如 `Take #3 · A001C012`：前半是这条 Take 在所在场次里的第几次，后半是主机位文件名去掉扩展名。**不同场都从 #1 开始计数**，所以一定要连文件名一起看，别只看 `Take #1`。
3. 卡片下方的机位槽位显示这次拍摄实际有哪几路：`A机 / B机 / C机 / AUX`。空槽位显示「无素材」——那表示这一路这次没拍到，不代表这条 Take 不存在。
4. 每张卡片会带状态标签：`AI/算法候选`、`待归集`、`已归集`、`已排除`。这些是当前进度提示，不是最终判断。

想按内容找，而不是按文件找：用「搜索」（`⌘K` / `Ctrl+K`）搜画面、对白或人工场记，例如「林雪推门后回头」。搜的是项目里已经生成好的证据，结果只是「可能相关的线索」，点进去仍然要自己确认。

找不到预期中的素材：先去「素材 → 素材库」看文件是否已经在这台机器上被识别。素材库提示「这条素材尚未进入项目索引」时，说明文件还没纳入项目，需要先做本机素材位置设置与扫描（见第 3 节 FAQ）。

### 第二步：看懂拍摄事实（素材 → 场记 / Take）

「**场记**」是拍摄事实的正式记录处。一行 = 一次实际拍摄记录。

- 一次拍摄的 A/B/C 多机位落在**同一行**：场号、镜号、次号只写一次，机位作为这一行的多路素材。
- 想新增：点「从 Take 加入」挑一条 Take，或「新建空白场记」手写一行。也可以把素材逐个加入当前场记行。
- 场记状态是现场语言：`未标记`、`可用`、`部分可用`、`NG`。**NG 是现场判断**，和审阅里的「排除」不是一回事（见术语表）。
- 可用的那一段用「入点 / 出点」标出来，也可以在备注里写场记原话、连续性提醒。
- 顶部要填「操作者」昵称：写入任何场记都要留人名。这是为了以后能追到「谁改的」，不是权限申请。
- **改了不等于存了**：界面会明确提示「保存后才写入项目」，改完记得点保存。

在「Take」视图选一条 Take，右侧详情会汇总：机位、场记状态、媒体是否可用、剧本归属。这三项合起来就是「这条素材现在到底是什么」。

播放器如果显示「当前设备未解析到这条媒体」或「素材无法读取」，不是素材坏了，是这台电脑还没找到文件——处理方式见 FAQ 第 1 条。

### 第三步：修正剧本位置（剧本 → 正文）

「剧本」回答的是「这个 Take 属于故事哪里」。剧本正文是主画布，顶部有三个显示模式：

- **正文**：剧本段。归集（placement）在这里改。
- **覆盖**：看每一段有没有素材、有没有候选。它只是显示方式，不产生新的事实。
- **问题**：看冲突和待处理项。

把 Take 归到剧本段：

1. 从「素材」或「审阅」带着当前 Take 走进「剧本」，顶部会出现「当前 Take」条。
2. 把这条 Take 拖到某个剧本段 = 精确归集，界面会提示「已人工归集 … → 当前剧本段」。
3. 拖到集数条 = 只记「这条属于第几集」，界面对此会明确提示（episode-only，见术语表）。**如果这条 Take 已经精确归到剧本段，拖到集数会把它替换成仅集数**，系统会先弹确认，别顺手确认。
4. 大量素材按范围归集：用「批量归集」，先写范围（例如 `1-10 第1集；11-20 第2集`），**先预览再确认**，不要盲确认。
5. 归错了：选中后「清除人工归集」。清除只撤销人的归集，不会改动自动分析结果。

两个必须知道的约定：

- 写归集需要「审核昵称」。归集是人做的决定，必须留名。
- 剧本顶部的摘要（剧本段 / 已归集 / 有候选 / 需处理）只是计数。「覆盖」只显示已经观察到的状态，**没有证据不等于缺镜头**，不要拿它当「这场没拍」的结论。

其它工作区想改归集时，正确做法是「在剧本中打开」并带着当前对象过去，而不是在别处再改一遍。

### 第四步：看片并做决定（审阅）

「审阅」是看片的地方，不是第二个素材库。

1. 左侧是看片队列，顶部按状态筛：**需关注 / Best / Keep / Reject**。想先处理麻烦的，就从「需关注」开始。
2. 右侧播放当前 Take。用「上一个 / 下一个」在队列里走，别用鼠标来回找列表。切换机位看同一时刻的其它角度。
3. 看完给这条 Take 一个**最终决定**：`Best`、`Keep` 或 `Reject`；也可以点「清除」回到「未决定」。写入要填操作者昵称，写成功后显示当前最终状态和修订号（例如 `r3`）。
4. 「需关注」列出这条 Take 目前值得看一眼的点（未归集、证据过期、待裁决的团队意见等）。它是**筛选和提示**，不会替你做决定。
5. 团队在 Team Web 里留下的意见会出现在这里，作为参考。个人意见不会自动变成最终决定。
6. 需要改素材事实或剧本位置时，用「在素材中打开」「在剧本中打开」带对象过去；要开始剪，用「到时间线」。

三个容易混的概念，务必分开：

| 你看到的 | 意思 | 谁说了算 |
| --- | --- | --- |
| 场记 `NG` | 现场判断这一条不好用 | 场记 / 现场 |
| 审阅「排除」 | 这条不进本次审阅范围 | 审阅时的整理动作 |
| 最终 `Reject` | 剪辑判断：这条不用 | 最终剪辑决定 |

「排除」和「恢复」在「素材 → 场记 → Review 归集辅助」里操作，池子分为：待归集 / 已归集 / 已排除 / 孤立素材。排除是审阅状态，**不等于场记 NG**，界面也会这样提示。

### 第五步：带进时间线（时间线）

1. 从「审阅」点「到时间线」，或在「素材」里带着 Take 进入「时间线」。时间线会把这条素材定位到 Source。
2. 在当前播放头**插入**或**覆盖**，继续排。时间线是唯一正式的剪辑面：粗剪建议、场记约束、覆盖建议都只是提案，必须你确认后才进入时间线。
3. 剪完做交付：在时间线的交付流程里先跑**交付前检查**。有阻塞项时界面会说「交付前检查未通过 · N 个阻塞项」，先回剪辑处理，不要跳过。
4. 检查通过后：
   - 「生成 Final Cut FCPXML」→ 需要时用「在 Final Cut Pro 打开」；
   - 「生成 Premiere XML」→ 用「系统打开 XML」，再到 Premiere Pro 里导入。
5. **改过剪辑就要重新生成**：已生成的交付文件对应某个剪辑版本，继续改动后按钮会变成「重新生成 …」，先重新生成再打开，避免拿旧文件去对片。

## 2. 术语表（用剪辑现场的话解释）

**Take**
一次真实拍摄。同一场会拍很多次，每次是一个 Take。镜序里的 Take 可以包含多路机位。

**机位 A / B / C（含 AUX）**
同一次拍摄的不同摄影机。A 机、B 机、C 机是并列的事实，不能合并成一个「景别」来判断；AUX 是辅助机位（航拍、空镜、GoPro、细节等）。同一次拍摄的 A/B/C 在场记里是同一行。

**场记（Slate）**
现场记录的拍摄事实：场号、镜号、次号、机位、状态、可用范围、备注。场记是「现场拍了什么」，不是「最后用哪条」。

**归集 / 剧本位置（placement）**
把一条 Take 对到剧本的某个位置。精确归集 = 对到具体剧本段；仅集数归集 = 只知道属于第几集。归集是人的判断，写的时候要留名。

**覆盖（Coverage）**
剧本的一种显示模式，用来看「哪些段已经有素材、哪些只有候选」。它是投影，不是新的工作台，也不代表「没证据就等于没拍」。

**需关注**
审阅里的筛选队列，聚合了未归集、证据过期、待裁决的团队意见等问题。它帮你先看该看的，不产生决定。

**剪辑决定（Best / Keep / Reject）**
看完片后对一条 Take 的人工判断。最终决定是**剪辑**的判断，和场记状态、审阅排除是三件不同的事，互不替代。

**排除（Exclude）**
审阅整理动作：这条暂时不进本次审阅范围。可以恢复。**不等于场记 NG，也不等于最终 Reject。**

**本机素材绑定**
镜序用一套与磁盘位置无关的媒体身份识别素材；「这台电脑上这个文件在哪」由本机绑定解决。所以素材换盘、换机器不会改变项目里对这条素材的事实，只需要重新告诉本机「文件现在在哪」。

**工作区**
存放项目的地方（一个目录）。项目数据、项目内的输入与输出都在工作区里；真实素材可以放在任何磁盘，由本机绑定指向。

**状态中心**
所有后台长任务的唯一入口：扫描、转写、匹配、人物识别、索引、打包等。取消扫描会停止任务，但不会破坏已有的本机素材连接。

**团队审阅（Team Web）**
可选的协作面，跑在浏览器里，用来收集团队的审阅意见。它不获得本机素材路径，也不替本机做最终决定。

## 3. FAQ

### 1）提示找不到素材 / 缺媒体，怎么办？

先看提示是哪一种：

- **「当前设备未解析到这条媒体」**：这台电脑还不知道文件在哪。
- **「素材无法读取 · 可能是素材盘未挂载或文件已移动」**：路径有，但盘没挂上或文件被挪走。

处理顺序：

1. 接上素材盘 / 重新挂载，然后点播放器里的「重试」。多数情况到这一步就好了。
2. 还不行，去「素材 → 素材库」或 Take 详情的「修复本机素材」，打开「本机素材恢复」：也可以从项目右键菜单里的「本机素材 / 换素材盘」进入。在里面设置本机素材位置；如果素材整体搬走了，选「素材移动后的新位置」。
3. 扫描是后台任务，进度在**状态中心**。取消扫描不会动你原来的本机素材连接；扫描失败时原连接也保持不变。
4. 文件确实不在手上：这条素材会明确显示缺媒体，不会假装能播。别用别的文件顶替，那会破坏媒体身份。

### 2）「仅归集到第 1 集」是什么？算没做完吗？

这是 **episode-only**：只知道这条 Take 属于第几集，还没精确到剧本段。

它是**合法的人工结果**，不是「待归集」，也不该被标成待处理。什么时候用它：素材太多、先按集划分，或者这条素材只可能用在某集但具体段落待定。要精确，就在「剧本 → 正文」里把它拖到具体剧本段。

反过来要小心：把已精确归集的 Take 拖到集数条，会把它替换成「仅集数」，界面会先问一次。

### 3）怎么和 Final Cut Pro / Premiere Pro 交接？

在「时间线」的交付流程里生成：

- **Final Cut Pro**：生成 Final Cut FCPXML，装好 Final Cut 的机器可以直接「在 Final Cut Pro 打开」。
- **Premiere Pro**：生成 Premiere XML，用「系统打开 XML」，然后在 Premiere 里导入。

几条纪律：

- 镜序**不改你的原始 FCPXML**，导出的是新文件。
- 改了剪辑就重新生成，再打开；不要拿上一版交付文件对片。
- 交付前检查有阻塞项时先处理，不要绕过。
- Resolve 目前没有交付适配（设置里显示为待完成），不要按 FCP/Premiere 的方式假设它能直接开。

### 4）Team Web 是什么？怎么让同事看片？

Team Web 是**浏览器里的团队审阅面**，独立于桌面 App 的本机审阅。它用来收集团队意见，不接管本机素材、场记和最终剪辑决定。

开启方式（桌面 App）：

1. 在左侧项目列表里对当前项目点右键（或选中后按 `Shift+F10`），选「团队审阅」。
2. 选访问范围：`局域网`（同事能访问）或 `仅本机`（只自己这台机器）。
3. 选安全模式：`首次配对`（同事第一次打开要输配对码）或 `可信局域网免配对`。
4. 点「开启团队审阅」，就绪后「复制协作链接」发给同事，或「在默认浏览器打开」自己先看一眼。
5. 同事第一次打开按当前安全模式完成配对，之后就能看片、留意见。

注意：

- 首次配对模式下，配对码显示在团队审阅面板里，别把它贴到公开群里。
- 关闭团队审阅不影响本机制作。
- 浏览器预览（非桌面 App）只能看界面，开不了真实的审阅服务。

### 5）数据存在哪里？会不会被上传？

- **项目数据**：在你打开的那个工作区目录里，按项目分开保存（项目定义、输入副本、分析结果、审阅与最终决定、缓存与输出）。
- **本机素材路径与绑定**：只保存在这台设备上，不进项目共享事实，所以换机器不会带着别人的磁盘路径跑。
- **团队审阅**：只有你主动「开启团队审阅」时，才通过本机服务在局域网内提供访问；关掉就没有对外入口。
- **模型服务**：默认用本机能力。如果你在「设置 → 小镜 → AI 能力」里把某项模型覆盖成外部服务地址，相关请求会发到你配置的那个服务——这是你自己填的地址，填之前想清楚数据能不能出去。
- API Key 只保存在当前设备，界面不会回显。

一句话：镜序不会偷偷上传你的项目；会往外走的东西，都是你显式配置或显式开启的。

### 6）会不会改我的原始素材、剧本、FCPXML？

不会。镜序把原始媒体、剧本、FCPXML 当作**输入**，只读引用：

- 播放是读文件，不是转码覆盖原文件。
- 导出的 FCPXML / Premiere XML 是新生成的文件。
- 删除项目时会明确提示：只删工作区内生成的项目目录、分析缓存和项目记录，**原始媒体、剧本与 FCPXML 不会删除**。

要保险，仍然建议原始素材盘按现场规矩只读挂载、项目输入单独留一份。

### 7）为什么有些按钮是灰的？

常见三种原因：

1. **浏览器预览**：直接在浏览器打开界面时，涉及本机文件、导出、团队审阅的动作会被禁用——这些必须在桌面 App 里做。
2. **没填操作者/审核昵称**：写场记、写归集、写最终决定都要留名，没填就写不了。
3. **前置条件没满足**：交付要先生成并通过交付前检查；打开 FCPXML 要求文件与当前剪辑版本一致。

### 8）AI 的建议会自己变成结论吗？

不会。AI、算法候选、语义搜索、素材审计、团队里的个人意见，都只是**线索或提案**。要变成场记事实、剧本归集、最终决定或时间线内容，必须有人确认并留名。系统也不会自动把素材判成「不要」。
